# Aprendizaje de programacion con Fortnite

## Proposito

Explorar, a partir de septiembre de 2026, si la aficion de mi nieto por Fortnite puede servir como puerta de entrada a la programacion, el diseno de juegos y la creacion tecnica.

El objetivo no es comercializar nada ni publicar islas de forma publica al principio, sino abrir una via de curiosidad: pasar de jugar a crear, probar, ajustar y entender que hay logica y programacion detras de las experiencias interactivas.

## Contexto

- Situacion: idea aplazada hasta estar asentado en casa tras la jubilacion.
- Punto de partida: desconocimiento inicial del ecosistema Fortnite Creative / UEFN / Verse.
- Enfoque: acompanamiento familiar, aprendizaje gradual y sin presion.
- Cautela: revisar controles parentales, privacidad, chat, compras y acceso a contenidos antes de empezar.

## Mapa inicial del ecosistema

### Fortnite Creative

Modo de creacion mas accesible dentro de Fortnite. Permite crear islas, escenarios, reglas sencillas, parkour, carreras, zonas de combate, escape rooms y minijuegos usando herramientas visuales.

Puede ser el primer paso porque no obliga a programar desde el principio.

### UEFN

Unreal Editor for Fortnite. Es una herramienta gratuita de Epic, basada en Unreal Engine, para crear experiencias mas avanzadas de Fortnite desde PC.

Permite trabajar con terrenos, objetos, iluminacion, dispositivos, reglas, pruebas y proyectos mas elaborados.

### Verse

Lenguaje de programacion usado en UEFN para definir logica del juego: eventos, condiciones, puntuaciones, comportamientos, puertas, plataformas, rondas, recompensas o interacciones.

Es la parte mas cercana a la programacion real, pero conviene llegar a ella despues de una primera experiencia visual y motivadora.

## Que se podria crear

- Una isla privada sencilla.
- Un circuito de carreras.
- Un parkour de varios niveles.
- Una arena 1v1.
- Una escape room.
- Un juego por equipos.
- Un sistema de puntuacion.
- Una puerta que se abre al cumplir una condicion.
- Plataformas que desaparecen o aparecen.
- Objetivos, marcadores, trampas o zonas especiales.
- [[../../20 - Notas enlazadas/Conceptos/conocimiento/npc-personaje-no-jugador|NPCs]] con comportamientos basicos.

## Que son los NPCs

Ver [[../../20 - Notas enlazadas/Conceptos/conocimiento/npc-personaje-no-jugador|NPC o personaje no jugador]].

En este proyecto interesan como ejemplo educativo porque permiten explicar eventos, condiciones, estados y decisiones de forma visual: un personaje puede reaccionar si el jugador se acerca, si entra en una zona, si lleva un objeto o si completa una prueba.

## Enfoque recomendado

### Fase 1: crear sin programar

Objetivo: una isla privada pequena y jugable.

Posibles retos:

- "Crea un parkour de cinco niveles".
- "Haz una carrera que se pueda completar en menos de dos minutos".
- "Disena una zona 1v1 equilibrada".
- "Prepara una mini escape room con tres pruebas".

La prioridad es que vea que puede construir algo propio.

### Fase 2: modificar una plantilla

Usar UEFN con una plantilla oficial o ejemplo sencillo. No empezar desde cero si eso genera friccion.

Aprendizajes posibles:

- que es un proyecto;
- como se prueba un cambio;
- que significa iterar;
- como corregir errores;
- como ordenar objetos y reglas.

### Fase 3: primera mecanica con Verse

Elegir una mecanica pequena:

- una puerta que se abre con una condicion;
- una plataforma que desaparece al pisarla;
- un contador de puntos;
- una zona que activa un evento;
- un NPC que reacciona al jugador.

La meta no es "aprender Verse", sino descubrir que programar sirve para que ocurran cosas en el juego.

## Criterios de seguridad y prudencia

- Revisar los controles parentales de Epic antes de empezar.
- Evitar compras, monetizacion o publicacion publica al principio.
- No compartir datos personales.
- No usar chat abierto sin supervision.
- Trabajar en islas privadas o entornos controlados.
- Separar el juego recreativo del proyecto creativo para que no se convierta en mas tiempo pasivo de pantalla.
