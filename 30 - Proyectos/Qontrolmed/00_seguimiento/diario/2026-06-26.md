En `maxgesth`:

```powershell

python -m compileall main.py src
```

Resultado: correcto.

Tambien se hizo microvalidacion de contrato en memoria:

- JSON version `1.1` con `features` se normaliza como export de resultados;
- `informes[*].observaciones` queda incluido en insercion de cabecera;
- resultado con `estado="NA"` y `valor_leido` como `"NA"` o vacio llega con
  `valor_leido = None` al insert de escritorio.

Validacion posterior con fixture fiel:

```powershell
python scripts\validate_preventivos_tablet_fixture.py
python -m py_compile scripts\validate_preventivos_tablet_fixture.py
```

Resultado: correcto. El fixture
`docs/fixtures/preventivos_tablet_paquete_a_1_1.json` fue generado desde el
exportador real de `maxgesth_port` y contiene un informe cerrado con
observaciones generales y dos resultados `NA`.

## Riesgos o notas

- La prueba real en APK/tablet sigue siendo obligatoria antes de cerrar el
  paquete como validado en campo.
- La cuota mensual de GitHub Actions bloquea la build remota; no es evidencia
  de fallo tecnico.
- Falta validar contra BD real o preproduccion que existan
  `informes_preventivo.observaciones` y soporte de `NA` en
  `resultados_preventivo.estado`.
