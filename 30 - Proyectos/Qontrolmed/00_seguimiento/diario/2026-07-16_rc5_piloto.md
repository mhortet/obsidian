# Inicio de RC5 y replanteamiento de septiembre

Fecha: 2026-07-16

## Decision

La salida prevista para septiembre se redefine como una implantacion piloto
controlada en una unica empresa para validar definitivamente el funcionamiento
real. No se plantea un despliegue masivo.

## Alcance de inicio

- actualizar dependencias vulnerables con version corregida;
- retirar `pdfkit` y `wkhtmltopdf` del paquete del piloto;
- unificar la manipulacion de PDF con `pypdf`;
- incorporar tests de politica de dependencias a CI;
- continuar despues con ACL del `.env` y backup/restauracion.

Los binarios conservados en `src/Compras/bin` son activos del modulo Compras,
que permanece aparcado para un desarrollo completo posterior. No se eliminan
en RC5; se excluyen del runtime y del paquete de la implantacion piloto.

## Tratamiento de PDF existentes

Todos los PDF presentes en el entorno son salidas sinteticas de pruebas
funcionales realizadas durante el desarrollo. No son registros reales, no
forman parte del historico operativo y no deben copiarse al entorno de la
empresa piloto. Las carpetas runtime correspondientes deben prepararse limpias
antes de cargar datos reales.

## Criterio de cierre del bloque

- tests y compilacion correctos;
- `pip-audit -r requirements.txt` sin vulnerabilidades conocidas;
- ausencia de `pdfkit`, `PyPDF2` y empaquetado de `wkhtmltopdf`;
- documentacion viva alineada con el piloto;
- cambios revisados antes de commit y publicacion.

## Validacion tecnica realizada

Se creo un entorno virtual temporal limpio con Python 3.13 y se instalaron las
dependencias declaradas desde cero.

Resultado:

- `pip-audit -r requirements.txt`: sin vulnerabilidades conocidas;
- 21 tests: correctos;
- compilacion de `main.py`, `src`, `scripts` y `tests`: correcta;
- `mysql-connector-python`: 9.7.0;
- Pillow: 12.3.0;
- pypdf: 6.14.2;
- prueba de creacion y union de PDF sintetico con `pypdf`: correcta.

Queda pendiente la validacion manual de una nueva RC empaquetada y la prueba
contra las bases de datos controladas antes de considerar terminado RC5.

## Correccion del procedimiento del `.env`

Se incorpora `scripts/configurar_qontrolmed_env.ps1`, que:

- requiere elevacion administrativa;
- corrige propietario y ACL del directorio `config`;
- crea `.env` desde `.env.example` si no existe;
- abre el editor desde el proceso elevado;
- reaplica al cerrar propietario y permisos del fichero;
- permite `-RepairOnly` para reparar sin editar.

El verificador comprueba ahora que Administradores es el propietario, que
Administradores y `SYSTEM` conservan control total, que Usuarios puede leer y
que Usuarios no conserva permisos de modificacion.

Validacion local:

- parser PowerShell correcto para los cuatro scripts de RC;
- 24 tests correctos;
- compilacion y `git diff --check` correctos.

Queda pendiente ejecutar el script elevado en un directorio temporal y repetir
despues la prueba con una RC instalada.

La ejecución elevada no pudo realizarse desde el agente porque el entorno no
proporciona un token UAC administrativo. El requisito
`#Requires -RunAsAdministrator` bloqueó el intento antes de crear el `.env`,
que es el comportamiento seguro esperado.
